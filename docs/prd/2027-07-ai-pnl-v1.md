# AI P&L v1 — run-cost unit economics + work-cost seats (M12 · Jul 2027)

> Status: Draft
> Owner: Prism CPO
> Last updated: 2026-07-06
> Related: [phase-2.md](../phase-2.md) §9 §10, [M2 PRD](2026-09-run-cost-visibility.md), [M6 PRD](2027-01-run-cost-attribution.md), [roadmap](README.md)

## Context / Problem

- The AI P&L has four buckets: **1 Build** (workforce indexes — the year's spine) · **2a Run** (product AI; stages ①–② live since M2/M6) · **2b Work** (AI in internal workflows — OpEx, scales with employees) · **3 Value** (deliberately deferred; never fabricated).
- What's missing for a defensible "AI P&L v1": 2a's **unit economics** (stage ③ — cost per use, per successful outcome) and 2b's **seat truth** (dormant seats, cost per active user — usually the biggest recoverable line item).
- Prism holds a join nobody else has: the spend side AND the workforce/harness indexes. "That function has seats and tools but low usage and no harness — a **training problem, not a procurement problem**" is a routing only Prism can make.
- This is the year capstone: one surface where a founder reads what AI costs to build with, to run, and to work with — every number a fetched fact or a gated derivation.

## Goals

- 2a stage ③ lights up where inputs exist: cost per 1k feature uses, cost per successful outcome, model-mix efficiency — all behind the tag-coverage gate.
- 2b MVP ships on fetched facts: seat inventory + activity → dormant seat rate and cost per active user, starting with the AI tools we can see (Claude seats × telemetry activity).
- The AI P&L summary surface assembles all buckets honestly: bucket 3 renders as "deferred by design", never as a number.
- At least one savings loop closes: an action taken (e.g. model-mix routing or dormant-seat reclaim) verified against the next bill via the adoption loop.

## Non-goals

- No revenue attribution, no "value of AI" dollars (bucket 3 stays deferred; the deferral is displayed, not hidden).
- No unit **process** cost for arbitrary internal workflows (per CV screened, per ticket resolved — needs per-org system-of-record connectors; year-two).
- No claim of "hours saved" — ever (standing verdict).
- No monetization-alignment KPIs beyond what customer-tier tag adoption already supports (stage ④ continues next year).

## Users / Personas

- **Founder / CFO**: reads the AI P&L summary — build, run, work — with coverage and confidence on every line.
- **Platform admin**: reclaims dormant seats; executes the routing/caching actions and watches the next-bill verification.
- **Function lead**: sees the training-vs-procurement verdict for their function's AI spend.

## User stories

- As a CFO, I want cost per 1k uses and per successful outcome per feature, so I can see which features make economic sense at scale.
- As a CFO, I want the dormant seat rate and cost per active user, so the easiest recoverable spend is visible this quarter.
- As a platform admin, I want a claimed saving verified against the next bill, so cost actions close with evidence instead of promises.
- As a function lead, I want the seats-vs-usage-vs-harness join, so "cancel the tool" and "train the team" stop being the same conversation.
- As the owner, I want bucket 3 explicitly marked deferred on the P&L surface, so our honesty discipline is visible exactly where every vendor fudges.

## Scope

**In scope**
- 2a stage ③ (gated by tag coverage): cost per 1k feature uses (prod cost ÷ uses), cost per successful outcome (prod cost ÷ completed tasks, where an outcome signal is connected), model-mix efficiency (calls on cheapest adequate model ÷ calls), cache-hit and prompt-size-creep trends where the provider/gateway exposes them.
- 2b seat MVP: seat inventory ingestion (Anthropic org seats first; seat list + price as fetched facts), 30-day activity from fleet telemetry → dormant seat rate, cost per active user per tool; additional tools enterable as manual contracts (declared facts, labeled as such).
- The workforce join: per function, seats + spend vs usage (bucket 1 Usage) + harness index → the keep / train / reassess verdict rendering (quadrant per spec).
- The AI P&L summary surface: bucket 1 (tokens + index summary, no dollars), 2a (billed run-cost with coverage), 2b (seat/work cost), bucket 3 (deferred banner) — one page, every line carrying its evidence badge.
- One verified-savings loop: recommendations from stage-③ findings (model-mix routing, dormant-seat reclaim) tracked through the adoption loop and checked against the following bill/invoice.

**Out of scope**
- SSO-wide tool discovery (2b's full tool map — year-two; v1 covers AI tools with APIs + manually declared contracts).
- Throughput/process-unit metrics from ATS/helpdesk/PM systems (year-two connectors).
- The 2a L1 composite index — publish only if coverage clears the gate by month end; otherwise the L2 views stand alone (honesty over headline).

## Functional requirements

- FR-1: Cost per 1k feature uses renders per feature where tags + use counts exist; the gate and the exact missing input are stated otherwise.
- FR-2: Cost per successful outcome renders where an outcome/completion signal is connected; failures are surfaced as making "calls cheap and outcomes expensive" per spec framing.
- FR-3: Model-mix efficiency renders from the tag ledger with the "cheapest adequate model" mapping published and editable per org (flagged defaults).
- FR-4: Seat inventory ingests as fetched facts (API where available, manual contract entry labeled as declared); no seat price is ever estimated.
- FR-5: Dormant seat rate = 0-activity-in-30d seats ÷ paid seats, computed from telemetry activity for covered tools; coverage of the activity signal is stated on the number.
- FR-6: Cost per active user per tool renders beside sticker price; both visible.
- FR-7: The keep/train/reassess quadrant renders per function from adoption (usage depth) × spend, with the harness index as the training-vs-procurement discriminator; verdicts are recommendations, never automatic actions.
- FR-8: The AI P&L summary page renders all four buckets with per-line evidence badges (fetched / derived-gated / deferred); bucket 3 shows the standing deferral statement.
- FR-9: At least one savings recommendation class flows through the adoption loop and is verified against the next provider bill/seat invoice, with the delta displayed.
- FR-10: All isolation rules hold: P&L surfaces read from the run-cost and roster/telemetry stores; nothing writes into workforce scoring.

## Non-functional requirements

- **Honesty**: every line item traceable to a fetched fact or a gated derivation; deferred means displayed-as-deferred.
- **Simplicity**: no new services; seat ingestion is another connector on existing rails; the P&L page is a read-layer composition.
- **Security**: billing/seat tokens server-side, read-only scopes.
- **Privacy**: 2b activity signals are seat-level presence (active/dormant), not behavioral detail; individual usage detail stays in the workforce product's privacy envelope.

## Open questions

- Process-unit definitions per function (Phase-2 §10-7) — deliberately deferred to year two with the connectors; record here so it doesn't silently return as a proxy.
- "Successful outcome" source for dogfood features (pipeline ok-status likely) and for pilot features (per-org definition) — W1.
- 2a L1 composite: publish this month if coverage ≥ gate, or hold to year two regardless? (CPO proposal: publish only behind the gate, low-confidence chip until two clean months.)

## Milestones

- W1: Stage-③ unit-economics computations behind the coverage gate + outcome-signal wiring.
- W2: Seat ingestion + dormant rate + cost per active user + manual contract entry.
- W3: Workforce join (quadrant + training-vs-procurement verdicts) + AI P&L summary page.
- W4: Verified-savings loop on ≥1 action class, year-end audit, ship gate + year-two proposal (2b tool map, stages ④–⑤, bucket-3 hooks).

## Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Tag coverage still below gate at pilot orgs | med | med | Unit economics stay honestly gated; seat-side (2b) value lands regardless |
| Seat APIs thinner than expected across tools | med | low | Manual contract entry as labeled declared facts; start with tools we can verify |
| Quadrant verdicts read as personnel judgments | low | high | Function-level only, recommendation framing, no per-person rendering |
| Capstone month overstuffed | med | med | 2b is deliberately an MVP (seats only); L1 composite optional behind the gate |

## Success metrics

- AI P&L summary renders for dogfood (and pilot if live) with every line badged fetched / gated / deferred — zero unbadged numbers.
- Dormant seat rate + cost per active user live on real seat + telemetry data.
- ≥1 feature with cost per 1k uses and ≥1 with cost per successful outcome (dogfood).
- One savings action verified against the following bill with the delta shown.
- Year-two proposal delivered off real learnings.
